# 工具设计与路由

[中文工具设计](./tool-design.zh-CN.md) | [English](./tool-design.en.md)

## 服务定位

汇智酒旅 B2B MCP Server 用于查询受控平台中的酒店候选和景区门票候选，不承诺实时库存、可订状态或预订成功。

所有请求使用独立 MCP 实例。每个请求携带 OAuth Bearer 访问令牌，并按 RFC 8693 Token Exchange 换取上游 OpenAPI Token。上游响应包含业务数据和限制说明时，应原样保留限制并避免夸大。

## 工具路由

| 用户意图                                     | 工具                           |
| -------------------------------------------- | ------------------------------ |
| 酒店、住宿、住哪里、酒店筛选或比较           | `hotel_search`                 |
| 景区、景点、乐园、门票或票价候选查询         | `ticket_search`                |
| 品牌识别但没有查询意图                       | 不调用工具，先询问酒店还是门票 |
| 机票、交通、演出、赛事、攻略、行程或订单售后 | 不调用任一工具                 |

只提供城市时，酒店只传 `destination`，门票只传 `cityName`。只提供景区名称时，门票只传 `scenicSpotKeyword`，不要用模型知识推断城市。

## hotel_search

用途：按目的地和可选条件查询酒店候选。

必填：

- `destination`：1–200 字符；城市中文名或英文名

可选：

- `hotel_name`：酒店名称关键词，不能填泛化推荐词
- `brand`：品牌关键词
- `stars`：最多 5 项，范围 0–5，可为小数
- `budget`：`min`、`max` 和可选币种；最低价和最高价均为非负
- `checkin_date`：`YYYY-MM-DD`，不得早于 UTC 当日
- `checkout_date`：晚于入住日期
- `limit`：1–6，默认 3

不支持入住人数、房间数、商圈、地标和排序。

未提供日期时，默认按当前 UTC 日期入住、次日离店，并在最终回答中说明实际采用的日期。酒店参考价是入住区间内匹配条件的每日起售价范围，不是具体房型实时价格或库存。

## ticket_search

用途：按城市或景区关键词查询景区门票候选。

至少提供以下一项，也可以同时提供两项：

- `cityName`
- `scenicSpotKeyword`

可选：

- `travelDateStart`：`YYYY-MM-DD`
- `travelDateEnd`：`YYYY-MM-DD`
- `budgetMin`、`budgetMax`：非负金额，可含小数
- `limit`：1–6，默认 3

不支持票种和人群筛选。每组条件调用一次，不按城市拆分为逐景区查询。只在用户修改条件或要求重查时再次调用。

未提供日期时，回答中应说明上游默认时间规则，不自行编造出行日期。`minPrice` 保留上游金额和币种，不换算单位；不代表实时价格或指定日期可订。

## 结果与展示

成功响应可能包含 MCP `content` 中的 Markdown、`structuredContent` 中的业务数据，以及可选的 MCP Apps 卡片元数据。优先展示工具返回的文本和卡片，并保留相关结构化数据、限制说明、图片及详情链接。不要依据结构化数据自行重建卡片或补造缺失字段。

空结果与错误要区分：

- 酒店或景区无候选：明确未找到，不放宽条件
- 景区存在但无门票产品：明确该景区未提供门票产品
- 参数校验失败：说明缺失或非法条件
- 认证或授权失败：说明需要完成 OAuth 授权，不暴露凭证
- 上游不可用或限流：说明暂不可查询，不自动重试

只使用受控配置生成详情链接，不接受模型指定任意 URL。
